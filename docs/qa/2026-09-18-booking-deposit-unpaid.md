# 신규예약 예약금 미납 선택 QA

## 변경 범위

- 신규예약 7단계에서 `납부 완료`와 `미납으로 예약`을 명시적으로 구분한다.
- 초기 상태는 둘 다 선택하지 않은 `수납 상태 미확인`이다.
- `납부 완료`는 기존처럼 예약금액과 현금/카드 수납 방법이 필요하다.
- `미납으로 예약`은 수납 방법과 추가 선납금 입력을 비활성화하고, 미납 확인 상태로 다음 단계 진행을 허용한다.

## 브라우저 검증

- 합성 환자 `합성당일환자 / SYN-SAME-001`만 사용했다.
- 상태 미선택 시 8단계와 `다음` 버튼이 비활성화됐다.
- `미납으로 예약` 선택 후 해당 radio가 선택되고 `미납 예약 확인 완료`가 표시됐다.
- 현금/카드 수납 및 추가 선납금 컨트롤은 비활성 상태를 유지했다.
- 8단계 최종 요약에 `예약금 미납 확인`이 표시됐다.
- 애플리케이션 오류는 없었고, 개발 서버의 `favicon.ico` 404만 확인됐다.

증빙: `output/playwright/qa-booking-deposit-unpaid.png`

## 저장 경계

- 환자 식별·검사·일정·예약 구분은 Backend에 저장된다.
- 예약금 상태는 현재 React-memory 정적 Prototype 데이터다. 예약 직후 화면과 편집 흐름에는 반영되지만 새로고침 후 영구 보존 및 Audit Log는 보장하지 않는다.
- 영구 보존이 필요하면 예약금 상태·금액·수납 방법·확인자·확인시각을 위한 별도 Backend 계약과 migration이 필요하다.
