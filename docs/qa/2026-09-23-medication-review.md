## QA 중 발견해 고친 문제

모두 이번 Sprint 화면 코드의 결함이며 커밋 전에 고쳤다.

1. 이미 유효한 결정에도 `의사 결정 다시 기록`이 주요 버튼(파란색)으로 보여 불필요한 재결정을
   부추겼다. 결정 대기와 재검토 필요일 때만 주요 버튼으로 두었다.
2. 의사 결정의 중단 일수 입력칸이 화면 폭 전체로 늘어났다. 숫자 입력 폭으로 줄였다.
3. 활성 의사 Profile이 없을 때 예약 등록 최종 확인이 `예약 저장 가능`으로 보이고 저장을 눌러야
   거절됐다. 5단계에 의사 확인으로 표시한 약이 있으면 검증 오류로 보여 주고 저장을 막는다.
4. 확인 업무 화면의 새 구역 이름이 예약 상세의 `인적사항 이중확인`과 겹쳐 E2E Locator가 둘을
   함께 잡았다. 구역 이름을 `이중확인 대기 현황`·`복용약 확인 대기 현황`으로 바꿨다.

## 따로 남긴 기존 문제

- 예약 등록 2단계 달력의 날짜별 `가능 N`은 지금 화면이 불러온 예약만으로 계산한다. 관리자
  화면이나 다른 주에서 Wizard를 열면 실제보다 많게 보일 수 있다(예: 마감된 9/25가 `가능 5`).
  선택한 날짜의 시간 목록과 저장은 Backend가 다시 검사하므로 중복 예약은 생기지 않는다.
  Sprint 3B부터 있던 동작이라 이번 범위에서 고치지 않고 별도 작업으로 넘겼다.
